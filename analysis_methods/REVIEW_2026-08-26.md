# Reconstruction review — 26 August 2026

## Corrected in this revision

1. Noise whitening was performed twice for `Body Coil 4Rx Coil` and once
   unconditionally for other probes. The preprocessed source is now always
   unwhitened, and whitening is applied exactly once when the reconstruction
   checkbox is selected.
2. The original 2026-08-26 revision selected receivers before whitening. This
   was changed on 2026-08-27 to match the requested workflow: the complete
   acquired receiver array is prewhitened first, and only then is the selected
   subset retained. Selected outputs are therefore virtual prewhitened channels.
   The GUI now displays the scanner's zero-based receiver IDs (`0..N-1`) while
   preserving MATLAB's one-based array indices internally.
3. The 3D zero-fill padding vector had the read and phase entries reversed.
   This was hidden by square matrices but padded the wrong axes for rectangular
   data.
4. The old `ifft3c` used `ifftn` across every non-singleton dimension and
   therefore Fourier-transformed the receiver dimension. It now transforms
   only read, phase and partition.
5. The centred inverse FFT used `fftshift`/`ifftshift` in the wrong order for
   odd matrix sizes. This produced a one-sample phase ramp for odd dimensions.
6. FOV-offset correction used matrix multiplication on 3D arrays, assigned a
   false kz coordinate to a singleton dimension, and treated 2D slice number
   as a Fourier partition coordinate. It now uses element-wise ramps and
   distinguishes 2D multislice from 3D.
7. The image display assumed square pixels. Magnitude, phase and map images now
   use the read and phase FOVs for their physical aspect ratio.
8. `ACS/Walsh` helpers called `isfield` on an `ImageReconCore` object and the
   ACS bias option could reference an undefined `maps` variable. Both paths
   now accept objects safely and create maps when needed.
9. The GUI showed `Adaptive` on first load while the object actually rebuilt
   with an unsupported `None` combination value (falling back to RSSQ). GUI
   and object defaults are now synchronised.
10. Updated 27 August: rotate/flip buttons previously warped both
    `originalcomplexkspace` and reconstructed arrays using `imwarp`. A rebuild
    then reapplied scanner FOV offsets to already rotated/interpolated k-space
    in the original read/phase axes, producing an apparent translation. Raw
    preprocessed k-space is now immutable. Offsets are applied once per fresh
    rebuild before the FFT, and the accumulated lossless rotation/reflection is
    applied to reconstructed images afterwards.

## Further recommendations

- `MapRelaxation` calls `ffc_t1map_phase_signed_run_parallel`, which in turn is
  documented as requiring `ffc_t1map_phase_signed_magnitude_worker_v2`; neither
  file is included in this archive. **Generate Relaxation Maps will fail**
  unless those functions happen to be on the user's MATLAB path. Add the two
  version-matched files to the project or restore a self-contained mapping
  implementation.
- The preprocessing path always treats a reduced phase matrix as symmetric
  undersampling about k0. Scans marked as genuine asymmetric partial Fourier
  need acquisition-side placement plus POCS/homodyne reconstruction rather
  than symmetric padding.
- The `obj.echoes > 1` branch unconditionally deletes echo 2 as a navigator.
  That rule should be tied to an explicit navigator sequence flag; it is not
  valid for a general multi-echo dataset.
- Prefer a separate noise-only prescan for covariance estimation when the
  console can provide one. Outer k-space is a practical fallback, but signal
  or coherent interference at the edges can bias the covariance.
- Add small anonymised 2D and 3D reference datasets with expected dimensions,
  orientation and intensity checks. Synthetic unit tests protect array logic;
  reference-data tests are still needed to verify console-specific header
  conventions and phase-ramp signs.
- Consider recording the estimated covariance condition number and whitening
  residual in the GUI. `whitening_info` is now stored on each reconstruction
  object as a starting point.
